# 用户画像：建立、使用与隐私

**什么情况下读我**：① 用户说“建立/查看/更新/删除我的画像”“这次不用画像”；② 第 4 步读取画像时；③ 第一次使用、没发现画像文件，需要引导时；④ 要在“给你的建议”里用到画像之前。

画像的作用只有一个：让“给你的建议”从泛泛而谈变成针对这个人。**画像不是解码的前提**，没有画像照样完整解码。

## 一、存在哪里、长什么样

- **路径**：用户主目录下的 `.plain-talk-decoder/profile.md`（Windows 即用户文件夹下的 `.plain-talk-decoder\profile.md`）。放在 Skill 目录之外，升级或重装 Skill 不会丢。
- **怎么读写**：用你自己的文件读写能力直接操作，**不经过任何脚本**。
- **没有本地文件能力**（不能读写文件时，与档位无关）：画像只在当次对话里有效；这类环境下没有现成文件可读，用户如果愿意，可以当场把自己的情况说一遍或贴给你。建画像的提问里就顺带说明：“我这次没法把你的情况存到本地，只在这次对话里记住，关掉就忘了。”

文件格式（人能直接读、直接改的 Markdown）：

```markdown
# 人话解码器 · 我的画像
状态：已建立            （或：已跳过）
最后更新：2026-11-20

## 身份与知识背景
- 职业/行业：
- 所在城市：
- 熟悉的领域：
- 不熟悉的领域：

## 关注点与在办的事
- 长期关注：
- 近期要做的决定：
  - （2026-11-20）想换一台手机

## 财务与风险偏好（可不填）
- 预算区间：
- 风险承受度：
- 家庭状况：

## 输出偏好
- 默认详略：标准版
- 默认语气：平实直白
- 默认联网核查：是
```

**记录原则**：

- 所有字段都可以留空；
- 只记**区间和概括性描述**（如“预算 3000 以内”“有房贷”），不记具体金额、证件号、银行卡号、账号、详细住址等精确敏感信息；
- 用户说了精确的敏感信息，不要原样记，改成概括（“月收入大致中等”）或干脆不记；
- “近期要做的决定”每条都带记录日期。

## 二、六个流程

### 流程 1：建立（首次引导，可跳过）

**触发**：第一次使用、没有发现画像文件，且用户没有说过“跳过”。

**不阻塞主流程**：用户带着链接来时，先问一句：

> “要不要花半分钟建个画像？这样我的建议会更贴合你的情况。也可以跳过，直接开始。”

- 问这一句时不阻塞：用户不回应、直接要结果，就先解码，报告末尾不再追问。
- 用户同意：用 3–5 个简短问题引导。如果你有结构化提问的能力，优先用；没有就用普通对话，一次问一两个问题。
- 引导问题（按需选，别一次全问）：
  1. 你做什么工作或在哪个行业？（决定解释深浅）
  2. 对科技、金融、政策这几块，哪块比较熟，哪块是外行？
  3. 最近有没有正要做的决定？（换手机、买保险、找工作、选课……）
  4. 如果方便，说下预算大概在什么区间、风险偏好稳妥还是激进？（可不答）
  5. 你希望默认给你详细点还是简短点？语气平实还是犀利点？
- 用户随时可以说“不想答了”“就这些”，立刻停止，已回答的保存。
- 建画像不要让用户等：先问两三个最关键的问题就开始解码，其余的在报告之后再补问。

**写入**：创建文件夹和文件，“状态：已建立”，写入当天日期。写完用一句话告诉用户存在哪里，以及“想看想改随时说”。

### 流程 2：跳过

用户说“跳过”“不用了”：

- **立刻开始解码**，不再追问；
- 能写文件时，创建文件，只含两行：“状态：已跳过”和“最后更新：当天日期”，并告诉用户：“我在你的用户文件夹里记了一下‘已跳过’，以后不会再问；想建画像随时说。”（悄悄在别人电脑上建文件不合适）。**之后不再主动询问**；
- **“跳过”和“这次不用”不一样**：用户说“跳过”“不用建了”“别问了”才算跳过。只说“先不用”“这次不用画像”，只表示当次不用，不写文件，下次可以再轻问一次；
- 
- 用户以后想建，说“建立画像”就行。

不能写文件时，只在本次对话里记住“用户选择跳过”。

### 流程 3：查看

用户说“查看我的画像”：

- 把文件内容用易读的方式展示给用户（可以直接贴文件内容，去掉空字段）；
- 没有文件：说“你还没有画像”，问是否要建立；
- 展示后问一句“有要改的吗？”

### 流程 4：更新

用户说“更新我的画像”或直接说“我换工作了”“我预算改了”：

- 只改用户提到的字段，其他不动；
- 更新“最后更新”日期；
- “近期要做的决定”新增一条带当天日期；已完成的决定可以问用户是否删除；
- 改完告诉用户改了什么。

**边用边补**：某次建议明显缺一条关键信息（如预算）时，可以在输出末尾问一句：“你的预算大概在什么范围？要不要记进画像？”**用户同意才写入**，不同意就只用在这一次。

### 流程 5：删除

用户说“删除我的画像”：

- 先确认一次：“这会把你的画像文件整个删掉，不能恢复。确定吗？”
- 确认后删除文件；告诉用户已删除；
- 用户只想删一部分（如“把预算那条删掉”）：只删那一条，不是整个文件；
- 文件本来就不存在：告诉用户“你还没有画像，没有东西可删”；
- 删除后本次对话不再追问是否重建；当次会话里记住的画像内容也一并忘掉；
- 不能删除文件（没有权限）：把文件位置告诉用户，请用户自己删除。

### 流程 6：过期确认

“近期要做的决定”每条都带日期。**超过 90 天**未更新的条目，在写“给你的建议”**之前**先确认（可以放在报告开头一句话问；用户没回应就本次不用）：

> “你之前在 8 月说想换手机，现在还打算换吗？”

- 用户说还在：更新日期，继续使用；
- 用户说不了：**本次不要用它**，并再问一句“要不要把这条从画像里删掉？”——用户同意才删除（同步更新“最后更新”日期）；用户说留着就保留，下次用到前仍先确认。跨年的日期写完整年月日，不要只写“8 月”；
- 用户没回答/不想答：本次不使用这一条。

## 三、使用规则（和隐私规则）

1. **只影响建议，不影响事实。** 画像只用于“给你的建议”一节和解释深浅。核心事实、滤镜拆解、可信度标注的**结论**，对所有用户必须一致。有没有画像，这几节的事实和判断应完全相同；允许不同的只有“解释深浅”——对外行多加术语注解和类比，对内行少讲，但不能增删事实和判断。解释术语时可以引入带“常见/通常”限定的品类常识（如“这类产品的免赔额常见 1 万元左右”），但**不能把品类典型值写成该产品的条款**，且要紧跟一句“这款具体是多少，必须问清/以条款为准”。
2. **不外传。** 画像内容：
   - **不写进联网搜索词**；
   - **不传给抓取脚本**；
   - **不传给任何第三方接口**；
   - 不写进任何日志。
3. **可追溯。** 建议里用到画像时，要说明依据，例如“按你说的预算在 3000 以内……”“你提到有房贷……”。这样用户能发现画像过时或写错。
4. **不迎合。** 不能因为画像显示用户喜欢某个品牌、已经倾向购买，就弱化风险提示。
5. **画像与内容对不上时，要点明。** 例如画像写的是“给孩子配保障”，而广告价格是“30 岁男性”，要在建议里写“这个价格不适用于孩子”，不要直接套用。
6. **按需使用。** 只用和本次内容相关的字段。看一条手机新闻，不要把用户的家庭状况也扯进来。
7. **敏感项更克制。** 财务与风险偏好是敏感信息：只在内容确实涉及消费或理财时才用；用的时候注明依据，但别在输出里把用户的财务状况复述一大遍。
8. **“这次不用画像”**：当次完全按无画像处理，不要读取、不要用，也不要因此修改文件。
9. **高风险领域**：画像不能让你突破边界。即使用户“风险承受度高”，也不能替用户做“买/不买”的决定。
10. **高风险场景的定制锚点**（供推导参考，按画像实际情况取用，不要机械照抄）：本金安全诉求 → 风险等级与投向、是否存款保险覆盖、历史上亏没亏过本金；临近退休或年长 → 流动性与提前赎回规则、急用钱时拿不拿得出来；大额资金 → 起购门槛与分散，不因“额度紧张”一次性全投；对领域不熟 → 每个关键术语多给一句通俗解释。拒绝替用户决定时，把两层原因都说清：这是高风险领域＋当前信息不足。依据可以合并注明（如“按你说的不能接受本金损失、这笔钱明年要用”），但每个用到的画像字段至少被引用一次。

## 四、有画像 / 无画像的建议对比（参考）

同一份虚构的保险广告，前面几节完全相同，只有“结合你的情况”不同：

- **无画像**：“如果你是想给孩子配一份保障的家长，重点看除外责任和续保条件；如果你已经有医保，没必要为了‘返还’多花钱。”
- **有画像**（32 岁，有房贷，孩子 2 岁，预算年交几千元，偏保守）：“按你说的有房贷、孩子还小、预算不高：先确认自己的保障够不够，再考虑这款。这页没写‘返还’要满足什么条件，预算紧的情况下中途断缴可能亏钱，先把返还条件和退保损失问清。”（注明了依据；不引入原文没有的条款事实；仍不替用户做“买不买”的决定。）

## 五、读取画像时的检查

- 文件存在吗？“状态”是已建立还是已跳过？
- 有没有超过 90 天的“近期要做的决定”？先确认再用。
- 有没有字段与当前内容无关？不用。
- 输出里有没有写明依据？
- 有没有把画像信息带进搜索词？**一条都不能带。**
