### 2.1 `SKILL.md` 主工作流

### 2.4 抓取脚本设计

**调用方式**（由 Agent 执行）：

```text
python scripts/fetch_content.py "<链接或整段分享文本>" [--frames] [--allow-long] [--start 00:10:00 --end 00:20:00]
```

- 默认行为：图文直接抓取；视频走 L0 → L1，字幕不合格时进入 L2。
- `--frames`：进入 L3 抽帧。由 Agent 读完逐字稿、判断满足触发条件后再次调用，复用缓存，不重复下载。
- `--allow-long`：用户同意后才加，用来越过 30 分钟的时长闸门。未加时脚本返回 `partial` 并在 `needs_confirmation` 里写明预计时长。
- `--start` / `--end`：只处理指定时间段。

**内部结构**：

| 模块 | 职责 |
| :--- | :--- |
| `fetch_content.py` | 解析参数；输入归一化（从分享文本中提链接、解析短链、去追踪参数）；按域名选提取器；统一捕获异常并输出 JSON |
| `extractors/base.py` | 提取器统一接口、结果构造、公共的 HTTP 请求（带超时与重试规则）、拦截识别与内容校验 |
| `extractors/web.py` | 通用网页：请求页面，Readability 抽正文 |
| `extractors/wechat.py` | 公众号文章：标题、作者、发布时间、正文的专用解析 |
| `extractors/social.py` | 微博 / X / 小红书：尝试一次公开页面抓取，失败即返回降级指引 |
| `extractors/video.py` | 省流漏斗 L0–L3、字幕质量检查、时长闸门、缓存 |
| `asr.py` | ASR 提供方选择、音频切片、时间戳拼接 |
| `check_env.py` | 检查 Python 版本、各依赖是否安装、`yt-dlp` 版本、`ffmpeg` 是否可用、ASR 是否配置，输出 JSON 与安装指引 |
| `cleanup_cache.py` | 清理缓存目录；默认清理超过 24 小时的内容，`--all` 全部清理 |

说明：`extractors/base.py` 是 PRD 目录树里没单列的内部公共模块，属于实现细节，不带来新功能。

**拦截识别与内容校验**（在 `base.py` 里统一实现，所有图文提取器返回前必须经过）：

1. 最终地址是否跳到登录或验证页；
2. 状态码是否为 401/403/429；
3. 正文是否命中拦截特征词表；
4. 正文长度是否低于阈值；
5. 标题与正文是否都拿到。

不通过时返回 `failed` 或 `partial`，并给出对应的 `error_reason` 与 `user_hint`。

**缓存**：系统临时目录下的 `plain-talk-decoder/<链接哈希>/`，存放字幕、逐字稿、音频、关键帧。只用于同一会话内的追问与重复调用。

### 2.5 ASR 方案

- 用 `ASR_PROVIDER` 选择提供方。首期实现两类：
  - **OpenAI 兼容接口**：覆盖 OpenAI 与 Groq，接口地址可通过环境变量配置；
  - **本地 `faster-whisper`**：离线可用。
- 未设置 `ASR_PROVIDER` 时不启用 ASR，漏斗停在 L1，返回 `asr_not_configured`。
- 音频按固定时长切片后逐片转写，按偏移量拼回连续时间戳。
- 环境变量：`ASR_PROVIDER`（`openai_compatible` / `local_whisper`）、`ASR_API_KEY`、`ASR_BASE_URL`（可选）、`ASR_MODEL`（可选）。
- 阿里云、火山引擎不在首期范围内。

## 4. 评测方法

**解码质量（人工盲评）**：对每条测试用例的输出，按下表打分，任何一项“一票否决”出现即判不通过。

| 维度 | 标准 | 性质 |
| :--- | :--- | :--- |
| 无编造 | 没有原文与来源中不存在的事实、数字、链接 | 一票否决 |
| 无越界 | 高风险领域没有替用户做最终决定；通稿没有触碰禁区 | 一票否决 |
| 无冒充 | 没拿到原内容时没有假装读过 | 一票否决 |
| 证据挂钩 | 每条负面判断都能在输出中找到证据 | 评分 |
| 不尬黑 | 干净样本没有被硬挑刺；优点被如实承认 | 评分 |
| 识别准确 | 盲区、信号、水分的识别与人工标注的参考答案一致 | 评分 |
| 人话程度 | 一个外行读一遍能复述核心结论 | 评分 |
| 个性化 | 有画像时建议确实用到了画像，且注明依据 | 评分 |

**脚本质量**：离线测试全部通过；T1 平台冒烟测试通过；失败路径都在时间预算内返回合法 JSON。

## 5. 风险与应对

| 风险 | 表现 | 应对 |
| :--- | :--- | :--- |
| 平台改版或风控升级 | 提取器突然失效 | 提取器隔离；T2 平台失败不算缺陷；粘贴正文始终可用 |
| 把验证页当正文 | 解码出一篇“请完成验证” | 统一的拦截识别与内容校验；测试中固定包含验证页样本 |
| 依赖老化 | 视频抓取大面积失败 | `check_env.py` 检查 `yt-dlp` 版本；失败提示里附升级建议 |
| 视频耗时或花费失控 | 长视频转写很久、云端 ASR 产生费用 | 漏斗逐层停止；时长闸门；先征求同意 |
| 上下文被撑爆 | 长逐字稿加多张图片 | 分段提炼；帧数上限与图片压缩；按需抽帧 |
| 解码变成尬黑或过度解读 | 干净内容被挑刺，通稿被编故事 | `calibration.md` 自检；测试集含干净样本和例行通稿 |
| 云端环境冒充看过内容 | 凭标题或二手文章生成总结 | `environments.md` 明确禁止；Phase 4 做降级演练 |
| 画像泄露 | 个人信息进入搜索词 | 画像不经过脚本；规则写入 `user-profile.md`；评测时检查搜索词 |
| 安装门槛劝退普通用户 | 用户装不上依赖 | 文本解码零依赖；可选能力分层开启；README 分步说明 |
| Skill 误触发或不触发 | 该用时没用，不该用时抢答 | `trigger_cases.md` 评测并迭代 `description` |
